# TaskFlow-API

RESTful веб-сервис планировщика задач с движком вычисления циклических интервалов, защищенной JWT-аутентификацией и персистентным хранилищем на SQLite.

---

## Архитектура и стек технологий

Сервис спроектирован по модульному принципу Standard Go Project Layout с изоляцией транспортного уровня, бизнес-логики и слоя данных:

* **Язык и среда**: Go 1.25.5.
* **HTTP-маршрутизация**: [chi v5](https://github.com/go-chi/chi) с цепочкой middleware (логирование запросов, восстановление после паник, валидация аутентификации).
* **Слой хранения данных**: SQLite c использованием чистого Go-драйвера [modernc.org/sqlite](https://gitlab.com/cznic/sqlite) и обертки [sqlx](https://github.com/jmoiron/sqlx). Приложение компилируется без CGO, что исключает внешние системные зависимости от gcc и упрощает развертывание в легковесных контейнерах.
* **Аутентификация**: [golang-jwt/jwt/v5](https://github.com/golang-jwt/jwt). Токены подписываются секретным ключом и передаются в HTTP-only cookie `token`.
* **Логирование**: Стандартный пакет `log/slog` для структурированного вывода событий в формате JSON/текст.
* **Контейнеризация**: Двухэтапная сборка (multi-stage) на базе `golang:1.25.5-alpine` и минимального рантайма `alpine:3.20`.
* **Тестирование**: Интеграционный тестовый набор на базе [testify](https://github.com/stretchr/testify).

## Ключевой функционал

### 1. Движок рекуррентных задач (NextDate Engine)

Бизнес-логика планировщика поддерживает вычисление следующей даты выполнения задач по настраиваемым паттернам повторения. Если дата задачи лежит в прошлом, алгоритм итеративно вычисляет ближайшую корректную дату строго позже текущего момента (`now`):

* `d <N>`: Интервал в днях. Шаг от 1 до 400 дней (например, `d 1`, `d 14`).
* `y`: Ежегодное повторение (+1 календарный год с коррекцией високосных лет).
* `w <дни>`: Повторение по дням недели (`1` — понедельник, `7` — воскресенье; например, `w 1,3,5`).
* `m <дни> [месяцы]`: Повторение по дням месяца и опциональному списку месяцев:
  * Положительные дни (`1..31`).
  * Смещение от конца месяца: `-1` (последний день), `-2` (предпоследний день).
  * Фильтрация по месяцам (`1..12`), например `m 1,-1 1,6,12`.

### 2. Жизненный цикл задач и REST API контракт

Сервис реализует идемпотентное управление состоянием через REST-эндпоинты:

* Создание (`POST /api/task`): Автоматическая нормализация даты (подстановка текущей даты, если значение не указано, либо первичное вычисление следующей даты по правилу).
* Завершение (`POST /api/task/done?id={id}`): Для циклических задач рассчитывается следующий шаг выполнения через `NextDate`, а запись в БД обновляется. Разовые задачи (без правила повторения) удаляются из базы.
* Поиск и фильтрация (`GET /api/tasks?search={query}`): Выборка ближайших задач с сортировкой по возрастанию даты. При передаче даты в формате `DD.MM.YYYY` выполняется точная фильтрация, при строковом запросе — регистронезависимый поиск по полям `title` и `comment`.

### 3. Защита эндпоинтов

Сервис поддерживает гибкий режим безопасности через переменную окружения `TODO_PASSWORD`:
* Если пароль задан, эндпоинты управления задачами защищаются middleware: доступ предоставляется только при наличии валидного JWT в cookie.
* Если переменная пуста или не задана, сервис работает в режиме открытого доступа без запроса пароля.

## REST API

| Метод | Путь | Описание | Доступ |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/signin` | Аутентификация по паролю и установка JWT в cookie | Публичный |
| `GET` | `/api/nextdate` | Утилитарный расчет следующей даты по параметрам запроса | Публичный |
| `GET` | `/api/tasks` | Получение списка задач с лимитом и поиском | Защищенный |
| `POST` | `/api/task` | Создание новой задачи | Защищенный |
| `GET` | `/api/task?id={id}` | Получение подробных данных задачи по идентификатору | Защищенный |
| `PUT` | `/api/task` | Редактирование существующей задачи | Защищенный |
| `DELETE` | `/api/task?id={id}` | Удаление задачи по идентификатору | Защищенный |
| `POST` | `/api/task/done?id={id}` | Отметка выполнения задачи (пересчет даты или удаление) | Защищенный |
| `GET` | `/*` | Раздача статического фронтенда из директории `web` | Публичный |

## Быстрый запуск

### Запуск через Docker

Сборка и старт контейнера с монтированием директории для сохранения базы данных:

```bash
# Сборка образа
docker build -t taskflow-api .

# Запуск контейнера
docker run -d \
  -p 7540:7540 \
  -e TODO_PORT=7540 \
  -e TODO_PASSWORD=secret \
  -v $(pwd)/data:/app/data \
  -e TODO_DBFILE=/app/data/scheduler.db \
  --name taskflow-api \
  taskflow-api
```

Сервис и встроенный веб-интерфейс будут доступны по адресу: `http://localhost:7540`.

### Локальный запуск

Требуется установленный Go 1.25+:

```bash
# Клонирование репозитория
git clone https://github.com/maximtsepaev/TaskFlow-API.git
cd TaskFlow-API

# Установка переменных и старт сервера
export TODO_PORT=7540
export TODO_PASSWORD=secret
go run ./cmd/server
```
